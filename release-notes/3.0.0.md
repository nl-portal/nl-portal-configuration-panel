Configuration panel 3.0.0 is the configuration panel for NL Portal 4.0. Already running the panel? See
[Upgrading from 2.0.0](#upgrading-from-200).

## Changes

- **New:** Verificatie, Form, and the portal interface settings (feature toggles and texts of the end-user portal).
  Every NL Portal 4.0 module can now be configured field by field.
- **Deprecated:** Product, DMN and Prefill (use Open Product).
- **Settings saved in the panel override NL Portal's own environment variables.** If you configured the portal
  interface or Verificatie through NL Portal's environment variables, saving those sections in the panel replaces them.
- **Default application name.** Examples now use `CLIENT_APPLICATION_NAME=nl-portal-app` (was
  `nl-portal-backend-libraries`). Configuration is stored per application name; if you used the old default, keep
  setting it.

## Breaking changes

- **Open Product settings must be entered again.** Configuration panel 2.0.0 saved them under a wrong key that no
  NL Portal version reads, so they are not copied. Enter them on the Open Product page. NL Portal 3.x reads the same
  key, so the settings apply to 3.x instances too.
- **Haal Centraal BRP and Ogone payment are removed** (removed from NL Portal 4.0). Their keys are listed in the notice
  for deletion.
- **An empty setting now means NL Portal's default.** The panel no longer saves empty fields or lists. In 2.0.0 a
  cleared field was saved as empty: a cleared document status whitelist, for example, hid every document. In 3.0.0
  clearing it brings back the default (`DEFINITIEF, GEARCHIVEERD`). Every field shows its default.
- **Both images run as a non-root user**: the backend as uid 1001, the frontend as uid 101. Check your
  `securityContext` and volume permissions. The frontend writes `config.js` on start, so it doesn't work with a
  read-only root filesystem.

## Under the hood

- **One registry for every configuration form.** The 18 hand-written feature forms are replaced by a single schema in
  `frontend/src/constants/sections.tsx`. A section is a list of typed fields (text, url, secret, number, toggle, enum,
  groups, SSL, named profiles, key-value maps, JSON), rendered by one shared component. Adding a module or a field is
  a data change, not a new form. Every field must declare NL Portal's default, so a missing default fails the build.
- **Prerequisites as data.** A section lists the sections it needs (`requires`); the panel warns when any of them is
  off.
- **Reusable upgrade path.** Moving keys for a new NL Portal version is a Liquibase changelog: it copies keys and marks
  the old ones with the version that stopped reading them. The notice on the main page and its delete actions work for
  any version, without panel code changes.
- **Up-to-date stack.** Spring Boot 4.1, Spring Cloud 5.0, Kotlin 2.4 and Gradle 9.8 on the backend; React 19.3,
  React Router 8, TypeScript 6, Vite 8, Node 24 and pnpm 11 on the frontend. The panel no longer depends on the
  `@nl-portal/*` npm packages.
- **Lint and licence headers enforced** with spotless (ktlint) on the backend and eslint on the frontend.
- **CI/CD like NL Portal's.** Pull request checks per stack, images built once and signed, and snapshot, release
  candidate and release channels.
- **Local development.** Docker Compose with `RUN_MODE` (`sources`, `local` or `remote`) runs next to the NL Portal
  stack without port clashes or hosts-file edits.

## Security

- Earlier backend images opened a remote debug port (8000). 3.0.0 images don't. Upgrade, or block port 8000, for every
  older backend image you run. To debug a 3.0.0 backend, add the agent through `JAVA_TOOL_OPTIONS`.

## Container images

- `ghcr.io/nl-portal/configuration-panel-backend:3.0.0`
- `ghcr.io/nl-portal/configuration-panel-frontend:3.0.0`

Releases are also tagged `3.0` and `3`; pin one of those. `latest` is the newest snapshot from `main`, not a release.
Images are signed with cosign:

```shell
cosign verify ghcr.io/nl-portal/configuration-panel-backend:3.0.0 \
  --certificate-identity "https://github.com/nl-portal/nl-portal-configuration-panel/.github/workflows/_build-app-image.yml@refs/heads/rc/3.0.0" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

## Upgrading from 2.0.0

Configuration panel 3.0.0 keeps serving NL Portal 3.x instances during the upgrade, so you can upgrade the panel first
and NL Portal at your own pace.

1. Upgrade the configuration panel to 3.0.0. On first start it copies the settings that moved in NL Portal 4.0 to their
   new keys, as they are, and keeps the old keys. NL Portal 3.x instances keep reading the old keys, NL Portal 4.0
   instances read the new ones.
2. **Check every configuration section** for broken or outdated values. Values are copied unchanged, empty ones
   included: an empty document status whitelist, for example, hides every document in NL Portal 4.0 just as it did in
   3.x.
3. Upgrade your NL Portal instances to 4.0.
4. When every connected NL Portal instance runs 4.0, delete the old keys from the notice on the panel's main page.
   Deleting doesn't notify NL Portal: an instance still on 3.x keeps the deleted values until it restarts, and only then
   loses them.

| Setting                            | NL Portal 3.x key (kept)             | NL Portal 4.0 key (copied)   |
|------------------------------------|--------------------------------------|------------------------------|
| Document confidentiality whitelist | Zaken API (`zaak-documenten-config`) | Documenten APIs              |
| Document status whitelist          | Zaken API (`zaak-documenten-config`) | Documenten APIs              |
| Theme logo and style               | `nl-portal.config.theme.*`           | `nl-portal.frontend.theme.*` |

Until you delete the old keys, changes to these settings in the panel reach NL Portal 4.0 only.

Direct payment profile languages are converted automatically from `nl-NL` / `en-GB` to `nl_NL` / `en_GB`, the format
Worldline and NL Portal use (also NL Portal 3.x's default).
